# 步骤4：代码精简

## GUARD

- 前置状态：步骤3 已勾选，审查轮状态行中本步为 `—`
- 幂等：重入时报告同名覆盖（`step4-simplify.md`），从头审查

## ACT

1. 读取里程碑期间修改的文件：`git diff --name-only {milestone-start-ref}`（基准从里程碑文档 `## Context` 读取，**禁止裸 `git diff`**，见契约「git 基准规则」）
2. **逐文件审查**：对每个变更文件，打开并阅读代码，按 `AGENTS.md` 约定的维度逐项检查：
   - 禁止只看文件名就判断「无问题」
   - 禁止跳过任何变更文件
   - 必须记录每个文件的审查结论（即使结论是「无问题」）
3. **登记发现**：每一处问题按契约「发现登记格式」分级登记入 Bugs 表（来源=步骤4代码精简，状态 ⬜）：
   - 🔴：精简引入的功能风险；🟡：可维护性差（过长函数、重复代码）；🟢：与 🔴/🟡 处置一致，本里程碑内修复
   - **不在本步骤就地修改**，登记后继续审查，打回统一在轮末
4. **生成报告**写入 `{version}-reports/step4-simplify.md`，必须包含：变更文件列表（全部审查过的文件）、每个文件的审查结论、发现的问题详情（如有）、总结结论（不少于 10 行）

## MARK

- 将状态行中本步由 `—` 更新为 `✓`（零发现）或 `✗`（存在任一发现），**更新后立即继续步骤5**
- 不在此处勾选、不在此处打回——判定权在轮末

## 门禁

本步零发现。轮末统一判断时，本步有任一发现即随审查轮一起打回。
