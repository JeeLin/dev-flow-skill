# 步骤2：设计核对

## GUARD

- 前置状态：步骤1 已勾选，Flow Status 步骤2 未勾选
- 幂等：重入时报告同名覆盖（`step2-design-review.md`），审查从头执行

## ACT

1. **必须执行**：调用 `skill` 工具，参数 `name: "mdflow-review"`，禁止自己生成报告
2. 加载技能后，**必须严格按照技能指令执行审查**，参数：
   - `type`: `design`
   - `dimensions`: 从 `AGENTS.md` 的 `## 审查维度` 读取的列表
   - `objects`: 里程碑文档路径 和 产品文档路径
   - `report_path`: `{version}-reports/step2-design-review.md`
3. 根据技能返回的结论（✅ 或 ❌）决定后续：
   - ✅ → 检查人工审核配置（见下），确认后进入 MARK
   - ❌ → 先将问题登记入里程碑文档 Bugs 表（标题、优先级 🔴/🟡、来源=步骤2设计审查、描述按契约「发现登记格式」），然后按严重程度处理：
     - **小问题**（仅措辞、细节缺失，不影响设计方向）：直接修改里程碑文档，保持步骤1勾选，重新执行本步骤。最多修正 3 次仍不通过，视为大问题
     - **大问题**（设计方向错误、产品边界不合理、子任务拆分粒度不当）：取消步骤1及后续勾选，执行**统一打回动作**（SKILL.md 状态机，含打回记录追加与状态行重置），重新进入步骤1

## MARK

- 满足门禁（报告 ✅ 且人工审核已确认）→ 勾选 Flow Status 步骤2

## 人工审核暂停（仅步骤2）

按 `AGENTS.md` 中 `## 设计审查配置` 的 `人工复核` 字段决定：

| 取值 | 行为 |
|------|------|
| 关闭 | 步骤2 完成后不暂停，自动继续 |
| 开启 | 步骤2 完成后暂停，等待用户确认后再继续 |
| 可选（默认） | 报告结论为 ❌ 时暂停人工确认；全 ✅ 则自动继续 |

> 步骤4/5/6/7 不设人工审核暂停，自动化审查直接判断门禁。

## 门禁

报告结论为 ✅ 且人工审核已确认（如需）。
