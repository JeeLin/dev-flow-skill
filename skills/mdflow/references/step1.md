# 步骤1：编写里程碑文档

## GUARD

- 前置状态：Flow Status 步骤1 未勾选
- 幂等：
  - 文档已存在但无新的打回要求（上次调用在创建后、勾选前中断）→ 不重建，检查字段完整性后续做
  - `## Context` 已含 `里程碑起始 ref:` → 不重新取 hash（重写文档时必须保留原值，避免中断后基准漂移）

## ACT

1. 检查 DEVELOPMENT.md 是否定义了下一个里程碑
   - 未定义或 DEVELOPMENT.md 为空：调用 `mdflow-planner` 技能进行规划，等用户确认后再继续
2. 从 DEVELOPMENT.md 读取下一个里程碑的核心功能、子任务预估、依赖关系、版本类型。**三态词汇与识别规则见契约「里程碑状态标记」**（唯一源，逐分支判定，不得跳支）。本步只做识别与读取；契约列出的「停止并报告」各分支一律停下回报，不自行提升、不做别名兼容。
   - **缺陷池搬入核对**：`## Bugs` 表内缺陷池 bug 已由 planner 逐条写入（描述列原样搬运、含 grep 锚点），本步**只读不改**、不重复搬运；若 `## Bugs` 表内无来源为「缺陷池」的行而 DEVELOPMENT 条目记有 `**缺陷池 bug**：{N} 个`，说明 planner 未完成搬入，**停止并报告**，不自行补写
   - **缺陷池搬入核对**：`## Bugs` 表内缺陷池 bug 已由 planner 逐条写入（描述列原样搬运、含 grep 锚点），本步**只读不改**、不重复搬运；若 `## Bugs` 表内无来源为「缺陷池」的行而 DEVELOPMENT 条目记有 `**缺陷池 bug**：{N} 个`，说明 planner 未完成搬入，**停止并报告**，不自行补写
3. 读取产品文档、开发文档、原型代码
4. 读取已完成的里程碑文档（如有），确定当前版本号与标识风格（以里程碑文档为准，不依赖项目文件中的版本字段）
5. 确定新里程碑版本号，风格沿用当前项目已有里程碑（语义版本取三段号最大者，序号取 M 后数字最大者）：
   - **语义版本风格**：patch=bug 修复/重构/文档；minor=新功能（里程碑默认）；major=破坏性变更
   - **序号风格**：M{n} → M{n+1}，递增类型仅影响版本类型标注，不改变编号方式
6. 按模板（`references/template.md`）创建里程碑文档，子任务拆到 1-2 个 commit 的粒度；写完立即执行**文件认领自查**（契约「子任务文件认领」）：解析各 `### N` 节的「文件结构」，任一 `文件:行号` 出现于 ≥2 节即检查该节「依赖」字段是否声明前序子任务编号，未声明或成环即**当场修正文档**，不留到步骤3
7. **点名核对**（写文档时）：详细设计凡点名既有代码目标（用例名、函数名、测试名、文件），必须同时给出该目标的 `文件:行号` 与现状内容摘要（`grep -n` 实读取得）。只写名字不写内容的点名视为未完成——下游会照名字误改无关代码
8. **文档改动声明**（契约「文档同步」，Docs-as-Code）：逐子任务在「文档改动」字段声明本任务将同步更新哪些对外文档（`文件` 粒度），无则写「无文档改动」。该声明是步骤3/8 核对的锚点，**不得留空**，也不得事后补写
9. 提交里程碑文档（**仅当路径未被 gitignore 时**）：
   - `git check-ignore -q {milestone-path}`：未被忽略 → `git add {milestone-path} && git commit -m "docs: create milestone {version}"`；已忽略 → 跳过
10. 记录里程碑起始 ref：
    - `git rev-parse HEAD` 获取 commit hash
    - 写入 `## Context`：`里程碑起始 ref: {commit-hash}`
    - 若第9步跳过了文档提交，重新读取文档写入（文件已变更未提交）

## MARK

- 勾选 Flow Status 步骤1

## 门禁

文档包含完整模板字段：Context（含里程碑起始 ref）、产品边界、子任务清单与详细设计、设计核对点、Flow Status（含审查轮状态行）、打回记录、Bugs；且**文件认领自查通过**（重叠认领已声明依赖顺序、无环）、点名既有目标均带 `文件:行号` 与现状摘要、**逐子任务「文档改动」字段已声明且非空**（契约「文档同步」）。

## 打回重入

步骤2 大问题打回会取消本步勾选。重入时按「打回记录」最新一行的原因重写文档；**保留打回记录不清空**（轮次按行数推算，清空会导致与状态行不一致），重写时保留已有的里程碑起始 ref。状态机不以打回记录作触发依据，保留不会引起重复打回。
