# 里程碑文档模板（template.md）

## 位置

默认 `.mdflow/milestones/{version}-{name}.md`，项目 `AGENTS.md` 可覆盖。

里程碑标识 `{version}` 支持两种风格：

- **语义版本风格**：`v{major}.{minor}.{patch}`（如 `v1.0.0-基础架构.md`），mdflow 默认，便于自动递增
- **序号风格**：`M{数字}`（如 `M30-sftp-mobile-adaptation.md`），按里程碑序号递增，常见于按迭代编号的项目

两种风格的报告目录均为 `{version}-reports/round{N}/`（如 `v0.1.0-reports/round1/`、`M30-reports/round2/`），位于 `.mdflow/milestones/` 下；{N}=审查轮状态行轮次（=打回记录行数+1），各轮报告分目录保留。

## 模板

```markdown
# {version}: {标题}

## Context
前序阶段完成了什么，本阶段在整体产品中的位置。
版本类型：patch（bug 修复/重构）/ minor（新功能，里程碑默认）/ major（破坏性变更），由步骤1根据里程碑内容自动判断
里程碑起始 ref: {commit-hash}（步骤1 填入，用于步骤4/5/7 的 git diff 基准）

## 产品边界
本阶段做什么、不做什么。

## 子任务清单

| # | 内容 | 状态 |
|---|------|------|
| 1 | ... | ⬜ |
| 1a | ...（子编号，可选） | ⬜ |
| 2 | ... | ⬜ |

## 子任务详细设计

### 1 {子任务标题}

- **功能目标**
- **文件结构**（创建/修改哪些文件）
- **接口设计**（API 端点 / 组件 props / 数据模型）
- **交互设计**（参考原型代码）
- **后端流程**
- **测试标准**
- **提交信息**（commit message）

**设计原则**：每个子任务应同时覆盖前后端功能，避免前后端分离开发导致集成问题

## 设计核对点

（根据项目约定列出本阶段的关键检查项）

## Flow Status

- 状态：进行中（进行中 / 已放弃，已放弃的文档由状态机排除，不参与当前里程碑选择）
- [ ] 步骤1：编写里程碑文档
- [ ] 步骤2：设计核对
- [ ] 步骤3：开发
- [ ] 步骤4：代码精简
- [ ] 步骤5：代码审查
- [ ] 步骤6：测试验证
- [ ] 步骤7：功能验收
- [ ] 步骤8：提交

审查轮：第1轮｜4— 5— 6— 7—

## 打回记录

（打回时在表格追加一条数据行；创建里程碑时无数据行，轮次 = 打回记录行数 + 1，与状态行初始 `第1轮` 一致）

| 时间 | 步骤 | 原因 |
|------|------|------|

## Bugs

| 状态 | 优先级 | 标题 | 来源 | 描述 |
|------|--------|------|------|------|

状态列取值：⬜ = 待修复（mdflow-bug 写入或步骤4/5/6/7 审查/发现问题时填入，状态机据此识别未修复 bug）；[x] = 已修复（步骤3 处理完后勾选）。优先级语义见 `references/contract.md` 严重度分级契约；描述列格式见契约「发现登记格式」。

## 沉淀候选

（步骤8 汇总写入；列定义唯一源见契约「沉淀候选格式」，创建里程碑时只放表头、无数据行）

| 序 | 来源 | 发现/模式 | 可 grep | 候选去向 | 草案（匹配模式 → 期望） | 出现轮次 | 裁决 |
|----|------|-----------|---------|----------|------------------------|----------|------|
```

## 字段语义

- **审查轮状态行**：格式与取值见 SKILL.md「状态机」；N = 打回记录行数 + 1，与初始 `第1轮` 一致。状态机只读勾选框与状态行。
- **打回记录**：打回时追加数据行；重写文档时**不清空**（轮次按行数推算，清空会导致计数与状态行不一致）。状态机不以打回记录作触发依据，保留不会引起重复打回。
- **子任务编号**：主编号用数字（1, 2, 3），拆分时用字母子编号（1a, 1b）；清单与详细设计的编号必须一一对应。
- **Context 的里程碑起始 ref**：由步骤1 用 `git rev-parse HEAD` 填入，见契约「git 基准规则」。
- **沉淀候选**：列定义唯一源为契约「沉淀候选格式」（模板只放表头）。`来源` 逗号分隔采集点（`round{N}/stepX` 报告 / `对话` / `历史`）；`出现轮次` 记轮报告出现的轮次（纯对话/历史填 `—`）；`裁决` 取值 ⬜ 待裁决（步骤8 只写 ⬜，台账纯记录）/ ✅ 接受（session 回头分析后呈请维护者裁决，由 session 半自动写入候选去向并过双门禁）/ ❌ 拒绝（留档不写入）。幂等：已裁决行不重置、台账只增不删。
