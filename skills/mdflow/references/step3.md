# 步骤3：开发（处理待办事项）

## GUARD

- 前置状态：步骤2 已勾选，Flow Status 步骤3 未勾选
- 幂等：子任务与 bug 处理本身按状态列（⬜/✅、⬜/[x]）续做，已完成的不重做

## ACT

1. 读取里程碑文档中的子任务清单、详细设计和 Bugs 表格
2. 先处理所有子任务（按详细设计实现代码，每个子任务完成后更新状态 ⬜ → ✅ 并提交），每动手一个子任务先过两道核对：
   - **依赖就绪**（契约「子任务文件认领」）：本子任务「依赖」字段声明的前序子任务未 ✅ 时不得动手，避免互相覆盖与行号位移
   - **点名核对**：详细设计若点名既有代码目标（用例名/函数名/文件），动手前按其 `文件:行号` 实读一遍，与文档描述不符即**停止该子任务并回报**，不照名字猜改
3. 所有子任务完成后，检查 Bugs 表格
4. 按优先级处理 bug：🔴 → 🟡 → 🟢（🟢 同样已登记入本表，一并处理）
5. 每个 bug 处理完后，在文档中勾选 [x] 并提交
6. 重复 4-5 直到所有 bug 处理完毕
7. **提交前自查**（契约「精简必查清单」，进步骤4 前完成）：对本里程碑变更（`git diff --name-only {milestone-start-ref}`）逐文件过一遍清单 8 项，命中的立即修复——这项是审查轮第一站，自查可省掉整轮打回重跑
8. **构建与测试验证**（契约「提交前验证」）：跑项目实际构建与测试命令（取 `AGENTS.md` 的 `## 质量门禁`），**未通过不得进入 MARK**，须先修到绿。shell 不可用导致本步无法验证时，**代码不得以未编译状态留在工作树**——先确认能编译再谈提交；纯文档里程碑无构建命令时记「本里程碑无构建步骤」后跳过，不得伪造通过
9. 满足门禁后进入 MARK

**处理顺序**：先完成所有子任务（子任务完成后，某些 bug 可能已不存在），再按优先级处理剩余 bug。

**原则**：每个 commit 只包含一个子功能点或一个 bug 修复；实现每个子任务后立即提交；修复每个 bug 后立即提交；不做文档外的大功能。

## MARK

- 勾选 Flow Status 步骤3（此后状态机按审查轮状态行进入步骤4）

## 门禁

所有子任务标记为 ✅、Bugs 表格中无 ⬜ 行（🔴/🟡/🟢 均需处理），**构建与测试通过**（契约「提交前验证」；无构建步骤的纯文档里程碑须已显式记录），且提交前自查（契约「精简必查清单」）已执行。
