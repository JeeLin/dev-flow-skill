# 步骤5：代码审查

## GUARD

- 前置状态：审查轮内步骤4 已执行完毕，状态行中本步为 `—`
- 幂等：重入时报告同名覆盖（`round{N}/step5-code-review.md`，轮内覆盖、跨轮写新目录），从头审查；分片形态见契约「报告清单」

## ACT

1. **必须执行**：调用 `skill` 工具，参数 `name: "mdflow-review"`，禁止自己生成报告
2. 加载技能后，**必须严格按照技能指令执行审查**，参数：
   - `type`: `code`
   - `dimensions`: **只在 `AGENTS.md` 存在 `## 代码审查维度` 段落时才传此参数**，值取该段内容；若没有该段落，则**不传** `dimensions`，让 mdflow-review 使用内置默认代码审查维度集。**严禁**把 `## 审查维度`（设计审查维度）当作代码审查维度传入——两套维度不同
   - `objects`: 变更文件列表（`git diff --name-only {milestone-start-ref}`，基准从 `## Context` 读取）
   - `report_path`: `{version}-reports/round{N}/step5-code-review.md`
3. **断言有效性必查**（跨 3 项目实证沉淀，维度见 `mdflow-review` 内置默认代码审查维度集第 7 项）：审查本里程碑新增或改动的测试与断言，逐条核对四类**无效断言**形态——
   - **恒真断言**：断言在任何输入下都成立（`assert!(x == x)`、与常量比较、只断言返回 `Ok` 而不校验内容）
   - **不可达输入组合**：构造的输入在真实调用链上不可达，断言永远不会被执行
   - **同义复述**：断言直接调用被测函数再与其返回值比较（`f(x) == f(x)` 式委派），没有独立期望值
   - **未被调用**：新增的测试或辅助函数在本里程碑变更内无任何调用点，实际不执行

   命中即按契约「发现登记格式」登记（🟢 也须登记，本里程碑内修复，不推迟下个版本）
4. **登记所有发现**：报告中的问题 🔴🟡🟢 **全部**处理，确保无一遗漏，登记入 Bugs 表（来源=步骤5代码审查，状态 ⬜，优先级严格沿用报告分级，描述按契约「发现登记格式」）：
   - 🟢 与 🔴/🟡 处置一致，本里程碑内修复，不推迟到下个版本

## MARK

- 将状态行中本步由 `—` 更新为 `✓`（零发现）或 `✗`（存在任一发现），**更新后立即继续步骤6**
- 不在此处勾选、不在此处打回——判定权在轮末

## 门禁

审查报告零发现（含断言有效性四类无效形态均已核对）。轮末统一判断时，本步为 ✗ 即随审查轮一起打回。
