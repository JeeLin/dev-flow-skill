# mdflow：里程碑开发流程

## 工作方式

你是里程碑开发流程的编排器。每次调用按固定顺序执行：读取基础数据 → 状态机判断当前步骤 → 读取对应步骤文件 → 执行一个步骤后停止。

### 循环与上下文管理

循环执行和上下文压缩通过平台内置命令实现，技能本身不包含循环逻辑：

- **连续执行**：使用连续调用机制（如 OMP 的 `/loop` 命令）定期自动调用技能，每次从里程碑文档读取状态，自动执行下一步
- **上下文压缩**：定期压缩上下文，避免对话过长
- **手动恢复**：上下文截断后直接调用技能，状态机从里程碑文档的 Flow Status 恢复进度

关键原则：所有状态写入里程碑文档，不依赖对话记忆。无论上下文如何变化，重新调用技能都能从文档中恢复。

**提交原则**：每次提交代码都必须同步更新里程碑文档的对应状态（子任务状态、Bugs 表格、Flow Status 勾选等），不允许只提交代码而不更新里程碑文档。里程碑文档本身的独立提交（步骤1 新建、步骤8 收尾）允许只含文档，不要求同时携带代码变更。

**Gitignore 处理**：若里程碑文档目录在 `.gitignore` 中（如 `.mdflow/milestones/`），步骤1/8 跳过文档的 git 提交，只提交代码变更和版本文件。里程碑状态仅保存在本地文件中，不进入 git 历史。文档创建不受影响。

## 基础数据

每次执行流程前，必须读取：

| 数据 | 路径 | 作用 | 必需 |
|------|------|------|------|
| 项目约定 | `AGENTS.md` | 技术栈、代码规范、目录结构、测试命令、审查维度 | 是 |
| 产品文档 | 默认 `docs/PRODUCT.md`，以 `AGENTS.md` 定义为准 | 产品定位、功能边界、用户可见流程 | 是 |
| 开发设计文档 | 默认 `docs/DEVELOPMENT.md`，以 `AGENTS.md` 定义为准 | 整体规划、里程碑划分、架构决策 | 是 |
| 原型代码 | 默认 `prototype/`，以 `AGENTS.md` 定义为准 | 前端交互参考、UI 布局参考 | 否 |

**前置检查**：执行前检查必需文件是否存在。如果 `AGENTS.md`、产品文档或开发设计文档缺失，提示用户先创建这些文件再执行 mdflow。

**Bug 收集**：里程碑文档创建后，用户可随时通过 `/mdflow-bug <描述>` 提交 bug，调用 `mdflow-bug` 技能写入当前里程碑文档的 Bugs 表格。

**里程碑规划**：如果 DEVELOPMENT.md 为空或未定义下一个里程碑，调用 `mdflow-planner` 技能进行规划，规划结果经用户确认后再继续步骤1。

**缺陷池消费**：`docs/BUGS.md` 中的待处理 bug（🔴/🟡/🟢）由 `mdflow-planner` 在规划下一个里程碑时统一纳入——全部转入该里程碑的修复范围（最终落到里程碑文档 `## Bugs` 表，⬜，来源标注「缺陷池」），并从缺陷池删除对应行，由步骤3 按 🔴→🟡→🟢 处理完毕。步骤1 在无下一个里程碑时会自动调用 planner，故缺陷池在每个新版本开始即被清空、不遗漏任何遗留 bug。

**里程碑起始 ref（{milestone-start-ref}）**：步骤1 创建里程碑文档时，将 `git rev-parse HEAD` 的结果写入 `## Context`（`里程碑起始 ref: {commit-hash}`），是全流程唯一的 diff 基准——不依赖 `HEAD~N` 计数，也不依赖 git tag（里程碑文档可能在 gitignored 目录）。

## 状态机

按顺序匹配，命中第一个即执行。每次调用执行一个步骤，执行完即停止（审查轮可拆到多次调用执行，但打回判断只在轮末进行一次）。

**状态唯一来源**：Flow Status 勾选框 + 其下方的「审查轮状态行」。报告文件只是审查证据，不参与状态判断，也不依赖对话记忆。连续执行通过平台连续调用机制实现。

状态机以里程碑文档的 Flow Status 为准。如果 Flow Status 显示某步骤已完成，但实际子任务状态不一致（如步骤3已勾选但子任务仍有 ⬜），以 Flow Status 为准继续推进，不回头补做。

**审查轮状态行**：位于 Flow Status 清单下方，格式 `审查轮：第{N}轮｜4□ 5□ 6□ 7□`。N = 打回记录行数 + 1；□ 取值 `—`（未执行）/ `✓`（通过）/ `✗`（不通过）。每步执行完立即更新本步符号，步骤3 开发期间不动；轮末四项全 ✓ 时才由轮末统一判断勾选步骤4/5/6/7。

**统一打回动作**（状态机内部动作，全流程仅此一处定义）：

1. 各审查步骤的发现已在轮内登记进 Bugs 表，不重复登记
2. 取消步骤3/4/5/6/7 的 Flow Status 勾选（步骤1/2 保持勾选）
3. 重置审查轮状态行：轮次+1（如 `审查轮：第2轮｜4✓ 5✗ 6✓ 7✗` → `审查轮：第3轮｜4— 5— 6— 7—`）
4. 在「打回记录」表格追加一行（一条记录本轮全部失败步骤与原因摘要）
5. 报告文件不改名、不删除；各轮报告写入 `round{N}/`（N=打回记录行数+1），旧轮目录整体保留作为打回证据，仅轮内重入（断点恢复）覆盖同名文件，跨轮写入 `round{N+1}/`
6. 提示用户：回到步骤3 批量修复（按 🔴→🟡→🟢 顺序），完成后开启新审查轮，按 4→5→6→7 **整轮重跑**（修复可能引入新问题，不做定点复验）

```
IF 没有里程碑文档，或全部里程碑均已结束（8 步全勾完成的进行中文档，或 `状态` 为 已放弃的文档）
  → 步骤1：创建新里程碑（如需规划，先调用 mdflow-planner）
ELSE 找到当前里程碑（.mdflow/milestones/ 中 `状态` 为 `进行中` 且未 8 步全勾的文档按标识排序取最大：语义版本按 vX.Y.Z 数值比较，序号风格按 M 后数字比较；`状态` 为 `已放弃` 的文档不参与选择）
  读取其 ## Flow Status：

  IF 步骤1 未勾选
    → 步骤1：编写里程碑文档

  IF 步骤2 未勾选
    → 步骤2：设计核对

  IF 步骤3 未勾选
    → 步骤3：开发（先完成子任务，再处理 bug）

  IF 步骤3 已勾选 且 审查轮状态行含 `—`（未执行项）
    → 审查轮进行中（断点恢复）：执行 4→5→6→7 顺序上第一个为 `—` 的步骤，完成后立即把状态行中本步改为 `✓`（通过）或 `✗`（不通过）

  IF 步骤3 已勾选 且 审查轮状态行的 4/5/6/7 均为 ✓/✗ 且（步骤4/5/6/7 未全勾 或 状态行含 ✗）
    → 轮末统一判断（步骤7 刚执行完、或轮末判断前被中断的恢复、或勾选框与状态行写入不一致的自愈）：
      · 四项全 ✓ → 勾选4/5/6/7
      · 任一 ✗ → 执行统一打回动作（一次性回到步骤3）

  IF 步骤3 已勾选 且 Bugs 表格存在未修复 bug（状态为 ⬜ 的行）
    → 执行统一打回动作（打回记录原因写「未修复 bug」），进入开发阶段按优先级修复全部未修复 bug，完成后由状态行恢复审查轮
    （注：审查轮进行中——状态行含 `—`、或四项已有结果待轮末判断——时本规则不触发，轮内步骤照常跑完，轮内新登记的 bug 在轮末统一处理）

  IF 步骤3 已勾选 且 审查轮状态行缺失 且 步骤4/5/6/7 未全勾
    → 兼容旧里程碑：初始化状态行为「第{打回记录行数+1}轮｜…」，已勾选的步骤填 `✓`、未勾选的填 `—`（覆盖旧里程碑审查轮进行到一半的情况），随后按 4→5→6→7 连续执行第一个为 `—` 的步骤（每步照常产报告、登记发现并更新状态行，中途不勾选、不打回、无短路），步骤7 更新完状态行后立即轮末统一判断

  IF 步骤8 未勾选
    → 步骤8：提交
```

**废弃里程碑**：当前里程碑无法继续（体积过大需拆分、方向错误等）时，在 `## Flow Status` 的 `状态` 字段设为 `已放弃`。状态机排除该文档，若无其它 `进行中` 里程碑则自动回到步骤1 规划新里程碑。废弃操作不产生打回记录，原文档保留作为历史。

## 步骤分发

| 步骤 | 名称 | 门禁（详述以步骤文件为准） | 步骤文件 |
|------|------|--------------------------|----------|
| 1 | 编写里程碑文档 | 模板字段完整 | `references/step1.md` |
| 2 | 设计核对 | 报告结论 ✅ 且人工审核已确认（如需） | `references/step2.md` |
| 3 | 开发 | 所有子任务 ✅ 且 Bugs 表无 ⬜ 行 | `references/step3.md` |
| 4 | 代码精简 | 本步零发现 | `references/step4.md` |
| 5 | 代码审查 | 本步零发现 | `references/step5.md` |
| 6 | 测试验证 | 测试+编译+Lint+覆盖率达标 | `references/step6.md` |
| 7 | 功能验收 | 轮末四项全 ✓（本步结论 ✅） | `references/step7.md` |
| 8 | 提交 | 所有检查通过；沉淀候选已汇总记录；汇报先于勾选 | `references/step8.md` |

**执行规则**：

1. 执行任一步骤前，必须先读取对应 `references/stepN.md`，严格按其执行；步骤文件是该步骤的唯一详述来源
2. **步骤2/4/5 必须调用 `skill` 工具加载 `mdflow-review`，步骤7 必须加载 `mdflow-acceptance`，禁止自行生成报告**
3. 跨步骤契约（严重度分级、发现登记格式、git 基准、审查职责、报告清单）见 `references/contract.md`
4. 里程碑文档模板与字段语义见 `references/template.md`
