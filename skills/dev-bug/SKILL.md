# dev-bug：记录 Bug

将用户报告的 bug 写入当前里程碑文档的 Bugs 表格。

## 输入

用户通过 `/issue <描述>` 或自然语言（如「有个bug：xxx」）提供 bug 描述。

## 执行步骤

1. **定位当前里程碑**：读取 `AGENTS.md` 获取里程碑目录路径（默认 `docs/milestones/`），找到版本号最大的未完成里程碑文档（Flow Status 中有未勾选步骤的文档）
   - 如果没有未完成的里程碑，提示用户先执行 dev-flow
2. **解析 bug 描述**：
   - **标题**：从描述中提取一句话概括
   - **优先级**：根据描述自动判断
     - 🔴 崩溃/无法使用/数据丢失/接口报错/阻塞性问题
     - 🟡 偶发/功能异常/体验问题/非阻塞性问题
     - 🟢 建议优化/锦上添花/轻微问题
3. **写入 Bugs 表格**：在里程碑文档的 `## Bugs` 表格末尾追加一行：

   ```
   | ⬜ | {优先级} | {标题} | 用户反馈 | {描述} |
   ```

4. **回复确认**：显示写入的内容，格式如：

   ```
   ✅ 已记录
   - 优先级：🟡
   - 标题：登录接口偶发 500
   - 描述：用户登录时偶尔返回 500 错误，刷新后正常
   ```

## 注意事项

- 状态列默认填 ⬜（未处理），由 dev-flow 步骤3 处理后改为 [x]
- 来源固定为「用户反馈」
- 如果有多个 bug，逐条分别写入
