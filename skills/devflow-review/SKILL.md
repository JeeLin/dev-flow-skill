# devflow-review：通用审查机制

本技能提供审查流程框架和报告模板，实际审查逻辑（具体检查维度）由调用方根据 `AGENTS.md` 中的 `## 审查维度` 定义。

## 适用场景

| 场景 | 调用方步骤 | 审查对象 | 输出报告 |
|------|------------|----------|----------|
| 设计审查（开发前） | dev-flow 步骤2 | 里程碑文档 vs 产品文档 | `step2-design-review.md` |
| 代码审查 | dev-flow 步骤5 | 代码变更（git diff） | `step5-code-review.md` |
| 设计再确认（开发后） | dev-flow 步骤7 | 已实现代码 vs 里程碑文档 | `step7-design-reconfirm.md` |

## 审查流程

### 0. 审查维度来源

- **design 类型**：使用 `AGENTS.md` 中 `## 审查维度`（设计审查维度）。
- **code 类型**：优先使用 `AGENTS.md` 中 `## 代码审查维度`；若该段缺失，回退到本技能内置默认代码审查维度集：

  | # | 维度 | 关注点 |
  |---|------|--------|
  | 1 | 正确性 | 逻辑错误、边界条件、空值/异常未处理 |
  | 2 | 安全性 | 注入（SQL/XSS）、敏感信息泄露、权限校验缺失 |
  | 3 | 健壮性 | 错误处理、资源释放（文件/连接）、并发安全 |
  | 4 | 可维护性 | 重复代码、过长函数、命名不清、耦合度 |
  | 5 | 性能 | 不必要的循环/查询、内存占用、N+1 问题 |
  | 6 | 规范 | 项目代码风格、提交信息格式 |

  内置默认集仅作兜底，不覆盖 `AGENTS.md` 中的显式定义。

### 1. 设计审查（步骤2 / 步骤7）

**目标**：验证设计合理性（步骤2）或实现正确性（步骤7）。

**流程**：
1. 读取 `AGENTS.md` 中的 `## 审查维度` 列表
2. 逐项检查每个维度：
   - 步骤2：对比里程碑文档与产品文档，确认设计符合产品边界
   - 步骤7：对比已实现代码与里程碑文档，确认实现符合设计
3. 记录发现：每个维度给出 ✅ 通过 / ❌ 不通过，并简要说明
4. 汇总结论：所有维度通过 → ✅；任一维度不通过 → ❌
5. 生成报告（见模板）

**通过标准**：报告结论为 ✅

### 2. 代码审查（步骤5）

**目标**：审查代码变更，分级问题严重程度。

**流程**：
1. 获取变更文件列表（`git diff --name-only`）
2. 逐文件审查变更内容
3. 对每个发现的问题分级：
   - 🔴 **必须修复**：安全漏洞、逻辑错误、破坏性变更、违反核心规范
   - 🟡 **应该修复**：性能问题、可维护性差、命名不规范
   - 🟢 **可选改进**：风格优化、次要重构建议
4. 记录每个问题的文件、行号、描述和严重程度
5. 生成报告（见模板）

**通过标准**：无 🔴 必须修复项

## 报告模板

### 设计审查报告（步骤2 / 步骤7）

```markdown
# {步骤名称}：{里程碑版本}

## 审查维度

| # | 维度 | 结论 | 说明 |
|---|------|------|------|
| 1 | {维度1} | ✅/❌ | {说明} |
| 2 | {维度2} | ✅/❌ | {说明} |

## 汇总

- **通过维度**：{N}/{总数}
- **结论**：✅ 通过 / ❌ 不通过

## 发现的问题

（仅列出 ❌ 的维度，若全通过则写"无"）
```

### 代码审查报告（步骤5）

```markdown
# 代码审查：{里程碑版本}

## 变更概览

- **变更文件**：{数量}
- **审查时间**：{时间}

## 问题列表

| # | 严重程度 | 文件 | 行号 | 描述 |
|---|----------|------|------|------|
| 1 | 🔴/🟡/🟢 | {file} | {line} | {description} |

## 汇总

- 🔴 必须修复：{数量}
- 🟡 应该修复：{数量}
- 🟢 可选改进：{数量}
- **结论**：{🔴数量} 个必须修复项（0 则通过）
```

## 使用方式

dev-flow 步骤调用本技能时，需提供：

1. **审查类型**：`design` 或 `code`
2. **审查维度**：从 `AGENTS.md` 读取的维度列表（design 类型为设计审查维度，code 类型为代码审查维度）
3. **变更文件**（code 类型）：`git diff` 输出或文件列表
4. **报告路径**：完整输出路径（由 dev-flow 根据步骤和版本号构造）

本技能负责：
- 按模板生成报告文件
- 根据审查结果计算结论
- 返回通过/不通过标志及报告路径

实际的维度检查逻辑（如何判断每个维度是否通过）由 dev-flow 步骤中的具体实现完成，本技能不包含项目特定的检查规则。
