# dev-flow：里程碑开发流程

## 工作方式

你是里程碑开发流程的编排器。每次调用时：

1. 读取项目的 `CLAUDE.md` 了解所有约定（产品定位、技术栈、目录结构、测试命令、代码规范等）
2. 在 `docs/milestones/` 中找到当前里程碑（编号最大的未完成文档）
3. 读取里程碑文档的 `## Flow Status` 判断当前步骤
4. **只执行当前这一步**，完成后更新状态，提示下一步

项目的所有路径和约定以 `CLAUDE.md` 为准。

## 状态检测

```
没有里程碑文档，或全部已完成？
  → 创建新里程碑（步骤1）

从步骤1到步骤8，找到第一个未勾选的步骤 N？
  → 执行步骤 N

步骤3的 Flow Status 未勾选，但子任务未全部完成？
  → 停在这里，提示用户继续开发，等子任务全部 ✅ 后再标记步骤3完成

步骤5/6/7执行完毕，报告结论不合格？
  → 打回：取消该步骤及后续步骤勾选，记录失败原因，提示修复内容
```

## 里程碑文档

### 位置

`docs/milestones/M{N}-{name}.md`，项目 `CLAUDE.md` 可覆盖。

### 模板

```markdown
# M{N}: {标题}

## Context
前序阶段完成了什么，本阶段在整体产品中的位置。

## 产品边界
本阶段做什么、不做什么。

## 子任务清单

| 子任务 | 内容 | 状态 |
|--------|------|------|
| 1 | ... | ⬜ |
| 2 | ... | ⬜ |

## 子任务详细设计

### 1 {子任务标题}

- **功能目标**
- **文件结构**（创建/修改哪些文件）
- **接口设计**（API 端点 / 组件 props / 数据模型）
- **交互设计**
- **后端流程**
- **测试标准**
- **提交信息**（commit message）

## 设计核对点

（根据项目约定列出本阶段的关键检查项）

## Flow Status

- [ ] 步骤1：编写里程碑文档
- [ ] 步骤2：设计核对
- [ ] 步骤3：开发
- [ ] 步骤4：代码精简
- [ ] 步骤5：代码审查
- [ ] 步骤6：测试验证
- [ ] 步骤7：设计再确认
- [ ] 步骤8：提交
```

## 报告

步骤2/4/5/6/7 的报告存放在 `docs/milestones/M{N}-reports/` 目录下，文件名格式 `step{N}-{name}.md`。每个报告包含审查结论，步骤5/6/7 以此判断门禁是否通过。

---

## 审查框架

步骤2（开发前）和步骤7（开发后）共用。基础维度：

- **产品定位**：是否符合项目定义的产品定位
- **架构一致**：是否符合项目约定的架构原则
- **边界清晰**：是否引入了产品文档未定义的概念
- **阶段完整**：是否跳过了前序阶段，是否提前实现了后续阶段
- **文档纯净**：是否把实现细节写进了产品文档
- **实现一致**（步骤7 专用）：代码实现是否与里程碑文档描述一致

`CLAUDE.md` 中定义的额外维度一并纳入检查。

## 步骤说明

### 步骤1：编写里程碑文档

1. 读取产品文档和开发文档，读取已完成的里程碑（如有）
2. 按模板创建里程碑文档，子任务拆分到 1-2 个 commit 的粒度
3. 勾选步骤1

**门禁**：文档包含完整模板字段（Context、产品边界、子任务清单、详细设计、Flow Status）

### 步骤2：设计核对

1. 按审查框架逐项检查里程碑文档
2. 报告写入 `M{N}-reports/step2-design-review.md`
3. 通过 → 勾选步骤2；不通过 → 列出问题，要求修改里程碑文档

**门禁**：结论为 ✅

### 步骤3：开发

1. 提示当前待完成的子任务
2. 协助逐个子任务开发，每完成一个 ⬜ → ✅
3. 全部完成 → 勾选步骤3

**原则**：按子任务逐个实现；每个 commit 只包含一个子功能点；不做文档外的大功能

**门禁**：所有子任务标记为 ✅

### 步骤4：代码精简

1. 读取最近修改的文件（git diff / git log）
2. 按 `CLAUDE.md` 中约定的维度检查并修复
3. 精简报告写入 `M{N}-reports/step4-simplify.md`
4. 勾选步骤4

**原则**：功能不变，只改组织方式；遵循项目现有风格

**门禁**：精简不改变功能行为

### 步骤5：代码审查

1. 按审查框架审查代码变更
2. 分类：🔴 必须修复 / 🟡 应该修复 / 🟢 可选改进
3. 审查报告写入 `M{N}-reports/step5-code-review.md`
4. 无 🔴 → 勾选步骤5；有 🔴 → 打回到步骤3

**门禁**：无 🔴 必须修复项

### 步骤6：测试验证

1. 从 `CLAUDE.md` 识别测试命令并运行
2. 测试报告写入 `M{N}-reports/step6-test.md`
3. 全部通过 → 勾选步骤6；有失败 → 打回到步骤3

**门禁**：所有测试命令通过

### 步骤7：设计再确认

1. 按审查框架验证已实现的代码
2. 确认报告写入 `M{N}-reports/step7-design-reconfirm.md`
3. 通过 → 勾选步骤7；不通过 → 打回到步骤3

**门禁**：结论为 ✅

### 步骤8：提交

1. 检查：commit 粒度（一子功能点一 commit）、commit message 格式、产品文档未被污染
2. 检查里程碑文档保留情况
3. 勾选步骤8，提示：里程碑已完成

**门禁**：所有检查通过
