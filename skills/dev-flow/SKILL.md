# dev-flow：里程碑开发流程

## 工作方式

你是里程碑开发流程的编排器。每次调用时，先读取基础数据，再进入状态机判断当前该做什么。

## 基础数据

每次执行流程前，必须读取：

| 数据 | 路径 | 作用 |
|------|------|------|
| 项目约定 | `CLAUDE.md` | 技术栈、代码规范、目录结构、测试命令、审查维度 |
| 产品文档 | 默认 `docs/PRODUCT.md`，以 `CLAUDE.md` 定义为准 | 产品定位、功能边界、用户可见流程 |
| 开发设计文档 | 默认 `docs/DEVELOPMENT.md`，以 `CLAUDE.md` 定义为准 | 整体规划、里程碑划分、架构决策 |
| 原型代码 | 默认 `prototype/`，以 `CLAUDE.md` 定义为准 | 前端交互参考、UI 布局参考 |

## 状态机

按顺序匹配，命中第一个即执行：

```
IF 没有里程碑文档，或全部已完成
  → 步骤1：创建新里程碑

ELSE 找到当前里程碑（docs/milestones/ 中编号最大的未完成文档）
  读取其 ## Flow Status：

  IF 步骤1 未勾选
    → 步骤1：编写里程碑文档

  IF 步骤2 未勾选
    → 步骤2：设计核对

  IF 步骤3 未勾选
    IF 子任务全部 ✅
      → 步骤3：标记完成
    ELSE
      → 暂停，提示用户继续开发，等全部 ✅ 后再调用 /dev-flow

  IF 步骤4 未勾选
    → 步骤4：代码精简

  IF 步骤5 未勾选
    → 步骤5：代码审查

  IF 步骤5 已勾选，但审查报告中有 🔴
    → 打回：取消步骤5及后续勾选，记录失败原因

  IF 步骤6 未勾选
    → 步骤6：测试验证

  IF 步骤6 已勾选，但测试报告中有失败项
    → 打回：取消步骤6及后续勾选，记录失败原因

  IF 步骤7 未勾选
    → 步骤7：设计再确认

  IF 步骤7 已勾选，但确认报告结论为 ❌
    → 打回：取消步骤7及后续勾选，记录失败原因

  IF 步骤8 未勾选
    → 步骤8：提交

  全部完成
    → 提示：里程碑已完成，可以开始下一个
```

## 里程碑文档

### 位置

默认 `docs/milestones/M{N}-{name}.md`，项目 `CLAUDE.md` 可覆盖。

### 模板

```markdown
# M{N}: {标题}

## Context
前序阶段完成了什么，本阶段在整体产品中的位置。

## 产品边界
本阶段做什么、不做什么。

## 子任务清单

| # | 内容 | 状态 |
|---|------|------|
| 1 | ... | ⬜ |
| 1a | ...（子编号，可选） | ⬜ |
| 2 | ... | ⬜ |

## 子任务详细设计

### 1 {子任务标题}

- **功能目标**
- **文件结构**（创建/修改哪些文件）
- **接口设计**（API 端点 / 组件 props / 数据模型）
- **交互设计**（参考原型代码）
- **后端流程**
- **测试标准**
- **提交信息**（commit message）

## 设计核对点

（根据项目约定列出本阶段的关键检查项）

## Flow Status

- [ ] 步骤1：编写里程碑文档
- [ ] 步骤2：设计核对
- [ ] 步骤3：开发
- [ ] 步骤4：代码精简
- [ ] 步骤5：代码审查
- [ ] 步骤6：测试验证
- [ ] 步骤7：设计再确认
- [ ] 步骤8：提交
```

子任务编号规则：主编号用数字（1, 2, 3），需要拆分时用字母子编号（1a, 1b）。子任务清单和详细设计中的编号必须一一对应。

## 报告

步骤2/4/5/6/7 的报告存放在 `docs/milestones/M{N}-reports/` 目录下：

| 步骤 | 文件名 | 内容 |
|------|--------|------|
| 2 | `step2-design-review.md` | 里程碑文档 vs 产品文档的审查结论 |
| 4 | `step4-simplify.md` | 代码精简检查结果 |
| 5 | `step5-code-review.md` | 代码审查发现和严重程度分级 |
| 6 | `step6-test.md` | 测试命令运行结果和覆盖率 |
| 7 | `step7-design-reconfirm.md` | 代码实现 vs 里程碑文档的确认结论 |

步骤5/6/7 的门禁判断依据是对应报告文件中的结论。

---

## 审查框架

步骤2和步骤7共用以下框架，但检查对象不同：

### 步骤2：检查里程碑文档（开发前）

对照产品文档，验证**设计是否合理**：

| 维度 | 检查内容 |
|------|----------|
| 产品定位 | 里程碑是否符合项目定义的产品定位 |
| 架构一致 | 设计方案是否符合项目约定的架构原则 |
| 边界清晰 | 是否引入了产品文档未定义的概念 |
| 阶段完整 | 是否跳过了前序阶段，是否提前实现了后续阶段 |
| 文档纯净 | 产品文档中是否混入了实现细节 |

### 步骤7：检查已实现代码（开发后）

对照里程碑文档，验证**实现是否正确**：

| 维度 | 检查内容 |
|------|----------|
| 实现一致 | 代码实现是否与里程碑文档描述一致 |
| 产品定位 | 最终产品行为是否符合产品定义 |
| 用户行为 | 用户可见行为是否与产品文档一致 |

`CLAUDE.md` 中定义的额外维度（如安全性、配置规范等）在两个阶段均纳入检查。

## 门禁与打回

| 步骤 | 门禁条件 | 不通过时 |
|------|----------|----------|
| 1 | 文档包含完整模板字段 | 重新编写 |
| 2 | 报告结论为 ✅ | 修改里程碑文档后重新核对 |
| 3 | 所有子任务标记为 ✅ | 继续开发 |
| 4 | 精简不改变功能行为 | 回退改动 |
| 5 | 审查报告无 🔴 | 打回到步骤3修复代码 |
| 6 | 测试报告全部通过 | 打回到步骤3修复代码 |
| 7 | 确认报告结论为 ✅ | 打回到步骤3修复代码 |
| 8 | 所有检查通过 | 修复后重新检查 |

打回动作（步骤5/6/7）：
1. 取消失败步骤及后续步骤的 Flow Status 勾选
2. 在里程碑文档中记录失败原因
3. 提示用户需要修复的内容

## 步骤详细说明

### 步骤1：编写里程碑文档

**触发条件**：里程碑文档不存在，或 Flow Status 步骤1 未勾选

1. 读取产品文档、开发文档、原型代码
2. 读取已完成的里程碑文档（如有）
3. 按模板创建里程碑文档，子任务拆分到 1-2 个 commit 的粒度
4. 勾选步骤1

**门禁**：文档包含完整模板字段（Context、产品边界、子任务清单与详细设计、设计核对点、Flow Status）

### 步骤2：设计核对

**触发条件**：步骤1已完成，Flow Status 步骤2 未勾选

1. 按审查框架的步骤2维度逐项检查里程碑文档
2. 报告写入 `M{N}-reports/step2-design-review.md`
3. 通过 → 勾选步骤2；不通过 → 列出问题，要求修改里程碑文档

**门禁**：报告结论为 ✅

### 步骤3：开发

**触发条件**：步骤2已完成，Flow Status 步骤3 未勾选，所有子任务为 ✅

1. 提示当前待完成的子任务
2. 协助逐个子任务开发，每完成一个 ⬜ → ✅
3. 全部完成 → 勾选步骤3

**原则**：按子任务逐个实现；每个 commit 只包含一个子功能点；不做文档外的大功能；参考原型代码确认交互细节

**门禁**：所有子任务标记为 ✅

### 步骤4：代码精简

**触发条件**：步骤3已完成，Flow Status 步骤4 未勾选

1. 读取最近修改的文件（git diff / git log）
2. 按 `CLAUDE.md` 中约定的维度检查并修复
3. 精简报告写入 `M{N}-reports/step4-simplify.md`
4. 勾选步骤4

**原则**：功能不变，只改组织方式；遵循项目现有风格

**门禁**：精简不改变功能行为

### 步骤5：代码审查

**触发条件**：步骤4已完成，Flow Status 步骤5 未勾选

1. 按审查框架的步骤7维度审查代码变更
2. 分类：🔴 必须修复 / 🟡 应该修复 / 🟢 可选改进
3. 审查报告写入 `M{N}-reports/step5-code-review.md`
4. 无 🔴 → 勾选步骤5；有 🔴 → 打回到步骤3

**门禁**：审查报告无 🔴 必须修复项

### 步骤6：测试验证

**触发条件**：步骤5已完成，Flow Status 步骤6 未勾选

1. 从 `CLAUDE.md` 识别测试命令并运行
2. 测试报告写入 `M{N}-reports/step6-test.md`
3. 全部通过 → 勾选步骤6；有失败 → 打回到步骤3

**门禁**：测试报告全部通过

### 步骤7：设计再确认

**触发条件**：步骤6已完成，Flow Status 步骤7 未勾选

1. 按审查框架的步骤7维度验证已实现的代码
2. 确认报告写入 `M{N}-reports/step7-design-reconfirm.md`
3. 通过 → 勾选步骤7；不通过 → 打回到步骤3

**门禁**：确认报告结论为 ✅

### 步骤8：提交

**触发条件**：步骤7已完成，Flow Status 步骤8 未勾选

1. 检查：commit 粒度（一子功能点一 commit）、commit message 格式、产品文档未被污染
2. 检查里程碑文档保留情况
3. 勾选步骤8，提示：里程碑已完成

**门禁**：所有检查通过
