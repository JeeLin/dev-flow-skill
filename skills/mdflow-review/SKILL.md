# mdflow-review：通用审查机制

本技能提供审查流程框架和报告模板。维度内容由 `AGENTS.md` 或调用方参数传入，本技能不包含项目特定的检查规则。职责：生成报告、计算结论、返回通过/不通过标志及报告路径。

## 输入参数

| 参数 | 说明 |
|------|------|
| `type` | `design`（设计审查）或 `code`（代码审查） |
| `dimensions` | 审查维度列表（来源规则见 §0，由调用方决定是否传入） |
| `objects` | design：里程碑文档与产品文档路径；code：变更文件列表 |
| `report_path` | 报告输出完整路径（由调用方构造） |

## 审查流程

### 0. 审查维度来源

- **design 类型**：使用 `AGENTS.md` 中 `## 审查维度`（设计审查维度）。
- **code 类型**：优先使用 `AGENTS.md` 中 `## 代码审查维度`；若该段缺失（调用方此时**不应传 `dimensions` 参数**），回退到本技能内置默认代码审查维度集：

  | # | 维度 | 关注点 |
  |---|------|--------|
  | 1 | 正确性 | 逻辑错误、边界条件、空值/异常未处理 |
  | 2 | 安全性 | 注入（SQL/XSS）、敏感信息泄露、权限校验缺失 |
  | 3 | 健壮性 | 错误处理、资源释放（文件/连接）、并发安全 |
  | 4 | 可维护性 | 重复代码、过长函数、命名不清、耦合度 |
  | 5 | 性能 | 不必要的循环/查询、内存占用、N+1 问题 |
  | 6 | 规范 | 项目代码风格、提交信息格式 |

  内置默认集仅作兜底，不覆盖 `AGENTS.md` 中的显式定义。

**风险加权**：按维度风险排序执行——正确性、安全性、健壮性（高风险）逐行精读；可维护性、性能、规范（低风险）以走查为主。风险排序只影响审查深度，不裁剪变更文件覆盖范围（全部文件必审）。

### 1. 设计审查（type=design）

**目标**：验证设计合理性。

**流程**：

1. 按维度来源规则确定维度列表
2. 逐项检查每个维度：对比里程碑文档与产品文档，确认设计符合产品边界
3. 记录发现：每个维度给出 ✅ 通过 / ❌ 不通过，并简要说明
4. 汇总结论：所有维度通过 → ✅；任一维度不通过 → ❌
5. 生成报告（见模板）

**通过标准**：报告结论为 ✅

### 2. 代码审查（type=code）

**目标**：审查代码变更，分级问题严重程度。

**流程**：

1. 获取变更文件列表与变更内容（由调用方传入，基准为里程碑起始 ref `{milestone-start-ref}`；**禁止**裸 `git diff --name-only`——开发阶段全部提交后其输出为空，会漏审全部变更导致假通过）
2. 逐文件审查变更内容
3. 对每个发现的问题分级。级别语义与处置见 mdflow `references/contract.md`「严重度分级契约」，本节仅列本入口特有判定关键词：
   - 🔴 **必须修复**：安全漏洞、逻辑错误、破坏性变更、违反核心规范
   - 🟡 **应该修复**：性能问题、可维护性差、命名不规范
   - 🟢 **可选改进**：风格优化、次要重构建议
4. 每个问题按契约「发现登记格式」记录文件、行号、证据与可证伪断言（禁概括式描述）
5. 生成报告（见模板）

**通过标准**：无 🔴 且 无 🟡 且 无 🟢（🔴/🟡/🟢 任一发现必须由调用方打回开发阶段解决，均阻断本步）

## 发现沉淀（两类审查通用）

报告末尾附「沉淀建议」段，对每条发现自问：**这类问题能否写成一条 grep 规则？** 能 → 给出规则草案（匹配模式 + 期望）；不能 → 写「无」。是否纳入检查脚本由调用方决定。

## 报告模板

### 设计审查报告

```markdown
# 设计审查：{里程碑版本}

## 审查维度

| # | 维度 | 结论 | 说明 |
|---|------|------|------|
| 1 | {维度1} | ✅/❌ | {说明} |
| 2 | {维度2} | ✅/❌ | {说明} |

## 汇总

- **通过维度**：{N}/{总数}
- **结论**：✅ 通过 / ❌ 不通过

## 发现的问题

（仅列出 ❌ 的维度，若全通过则写"无"）

## 沉淀建议

（无则写"无"）
```

### 代码审查报告

```markdown
# 代码审查：{里程碑版本}

## 变更概览

- **变更文件**：{数量}
- **审查时间**：{时间}

## 问题列表

| # | 严重程度 | 文件 | 行号 | 描述 |
|---|----------|------|------|------|
| 1 | 🔴/🟡/🟢 | {file} | {line} | {description} |

## 汇总

- 🔴 必须修复：{数量}
- 🟡 应该修复：{数量}
- 🟢 可选改进：{数量}
- **结论**：{🔴数量} 个必须修复 + {🟡数量} 个应该修复 + {🟢数量} 个可选改进（三者均为 0 则通过；任一发现均阻断本步）

## 沉淀建议

（无则写"无"）
```
