# mdflow-review：通用审查机制

本技能提供审查流程框架和报告模板。维度内容由 `AGENTS.md`、调用方参数或 mdflow 契约（`simplify` 类型）传入，本技能不包含项目特定的检查规则。职责：生成报告、计算结论、返回通过/不通过标志及报告路径。

## 输入参数

| 参数 | 说明 |
|------|------|
| `type` | `design`（设计审查）、`simplify`（精简审查）或 `code`（代码审查） |
| `dimensions` | 审查维度列表（来源规则见 §0，由调用方决定是否传入） |
| `objects` | design：里程碑文档与产品文档路径；code：变更文件列表 |
| `report_path` | 报告输出完整路径（由调用方构造） |

## 审查流程

### 0. 审查维度来源

- **design 类型**：优先使用 `AGENTS.md` 中 `## 审查维度`（设计审查维度）；若该段缺失（调用方此时**不应传 `dimensions` 参数**），回退到本技能内置默认设计审查维度集：

  | # | 维度 | 关注点 |
  |---|------|--------|
  | 1 | 产品边界 | 设计是否落在 `PRODUCT.md` 功能边界内，无规格外功能 |
  | 2 | 设计完整性 | 子任务/接口/数据结构是否覆盖目标，是否缺失必要字段 |
  | 3 | 一致性 | 与既有架构与产品文档约定是否冲突 |
  | 4 | 可实现性 | 子任务拆分粒度、依赖关系是否落地可行 |
  | 5 | 风险 | 是否引入明显风险（数据一致性/安全/破坏性变更） |

  内置默认集仅作兜底，不覆盖 `AGENTS.md` 中的显式定义。
- **simplify 类型**：不读 `AGENTS.md`，固定使用 mdflow `references/contract.md` 的「精简必查清单」（跨项目实证沉淀的唯一源；调用方**不传 `dimensions` 参数**）。不与 `code` 的质量维度重叠。
- **code 类型**：优先使用 `AGENTS.md` 中 `## 代码审查维度`；若该段缺失（调用方此时**不应传 `dimensions` 参数**），回退到本技能内置默认代码审查维度集：

  | # | 维度 | 关注点 |
  |---|------|--------|
  | 1 | 正确性 | 逻辑错误、边界条件、空值/异常未处理 |
  | 2 | 安全性 | 注入（SQL/XSS）、敏感信息泄露、权限校验缺失 |
  | 3 | 健壮性 | 错误处理、资源释放（文件/连接）、并发安全、生产代码裸 `unwrap()`/`expect()` |
  | 4 | 可维护性 | 重复代码、死代码/未使用导出、过长函数、命名不清、注释与实现不符、耦合度 |
  | 5 | 性能 | 不必要的循环/查询、内存占用、N+1 问题 |
  | 6 | 规范 | 项目代码风格、提交信息格式 |

  内置默认集仅作兜底，不覆盖 `AGENTS.md` 中的显式定义。

**风险加权**：按维度风险排序执行——正确性、安全性、健壮性（高风险）逐行精读；可维护性、性能、规范（低风险）以走查为主。风险排序只影响审查深度，不裁剪变更文件覆盖范围（全部文件必审）；simplify 类型仅回答可精简性，全部变更逐行精读。

### 1. 设计审查（type=design）

**目标**：验证设计合理性。

**流程**：

1. 按维度来源规则确定维度列表
2. 逐项检查每个维度：对比里程碑文档与产品文档，确认设计符合产品边界
3. 记录发现：每个维度给出 ✅ 通过 / ❌ 不通过，并简要说明
4. 汇总结论：所有维度通过 → ✅；任一维度不通过 → ❌
5. 生成报告（见模板）

**通过标准**：报告结论为 ✅

### 2. 代码审查（type=code）

**目标**：审查代码变更，分级问题严重程度。

**流程**：

1. 获取变更文件列表与变更内容（由调用方传入，基准为里程碑起始 ref `{milestone-start-ref}`；**禁止**裸 `git diff --name-only`——开发阶段全部提交后其输出为空，会漏审全部变更导致假通过）
2. 逐文件审查变更内容
3. 对每个发现的问题分级。级别语义与处置见 mdflow `references/contract.md`「严重度分级契约」，本节仅列本入口特有判定关键词：
   - 🔴 **必须修复**：安全漏洞、逻辑错误、破坏性变更、违反核心规范
   - 🟡 **应该修复**：性能问题、可维护性差、命名不规范
   - 🟢 **可选改进**：风格优化、次要重构建议
4. 每个问题按契约「发现登记格式」记录文件、行号、证据与可证伪断言（禁概括式描述）
5. 生成报告（见模板）

**通过标准**：无 🔴 且 无 🟡 且 无 🟢（🔴/🟡/🟢 任一发现必须由调用方打回开发阶段解决，均阻断本步）

### 3. 精简审查（type=simplify）

**目标**：只回答「代码里有没有可删可并可收敛的冗余」，维度固定为 mdflow `references/contract.md` 的「精简必查清单」（死代码/重复逻辑/过长/命名注释不符/跨层依赖/裸 `unwrap()`/`expect()`/硬编码/错误处理不一致），**不重复** `code` 的质量维度。

**流程**：

1. 维度清单见契约「精简必查清单」（调用方**不传** `dimensions` 参数）
2. 获取变更文件列表与变更内容（由调用方传入 `objects`，基准为里程碑起始 ref；**禁止**裸 `git diff --name-only`——开发阶段全部提交后其输出为空，会漏审全部变更导致假通过）
3. 逐文件审查变更实现：判断清单每一项是否命中，**必须读实现**（不能只看文件名），记录每个文件的审查结论
4. 对命中项分级。级别语义与处置见契约「严重度分级契约」，本入口判定关键词：
   - 🔴 **必须修复**：精简可能引入功能风险的疑点（删除被间接引用的代码、合并存在副作用差异的逻辑）
   - 🟡 **应该修复**：清单命中的冗余（死代码/重复/过长/命名注释不符/跨层依赖/裸 `unwrap()`/`expect()`/硬编码/错误处理不一致）
   - 🟢 **可选改进**：清单项的轻微变体（处置与 🔴/🟡 一致，本里程碑内解决）
5. 按契约「发现登记格式」记录，含**去重**（同 `文件:行号` 已在 Bugs 表登记不重复登记）；生成报告（见「精简审查报告」模板）

**通过标准**：无 🔴 且 无 🟡 且 无 🟢（任一发现均阻断，与 `code` 类型相同）。

## 发现沉淀（三类审查通用）

报告末尾附「沉淀建议」固定表格（列定义唯一源见契约「沉淀建议格式」），对每条发现自问：**这类问题能否写成一条 grep 规则？** 能 → 给出规则草案（匹配模式 + 期望）并填 `候选去向`；不能 → 占位行 `— | 无 | — | — | — |`。`候选去向` 仅为建议，步骤8 由 session 扫描各轮报告汇总入里程碑文档 `## 沉淀候选` 台账，维护者 Accept/Reject 后才落地。

## 报告模板

### 设计审查报告

```markdown
# 设计审查：{里程碑版本}

## 审查维度

| # | 维度 | 结论 | 说明 |
|---|------|------|------|
| 1 | {维度1} | ✅/❌ | {说明} |
| 2 | {维度2} | ✅/❌ | {说明} |

## 汇总

- **通过维度**：{N}/{总数}
- **结论**：✅ 通过 / ❌ 不通过

## 发现的问题

（仅列出 ❌ 的维度，若全通过则写"无"）

## 沉淀建议

| 序 | 发现/模式 | 可 grep | 候选去向 | 草案（匹配模式 → 期望） |
|----|----------|---------|----------|----------------------|
| 1  | {描述} | ✅ / ❌ | `check.sh` / `AGENTS.md 维度` / `技能侧` / — | `{pattern}` → {expected}；不可则 — |
| …  | … | … | … | … |

（ 无则填 `— | 无 | — | — | — |`；`候选去向` 仅为建议，最终去向由维护者在步骤8 汇总时决定是否写入 `check.sh` / `AGENTS.md 维度` / 技能侧硬规则。）


```
