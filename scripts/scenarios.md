# 状态机场景清单（二期夹具测试底稿）

一期 `check.sh` 只做静态 grep。二期将下列场景做成 `scripts/fixtures/` 下的里程碑文档夹具，逐条推演状态机并断言输出。

**断言字段统一为**：`Flow Status 勾选`、`审查轮状态行`、`打回记录行数`、`Bugs 表`、`报告文件`、`下一步动作`。

## 运行与维护

二期场景推演由 `scripts/run-scenarios.sh` 驱动，读取 `scripts/fixtures/SNN.md` 的里程碑夹具，逐条推演状态机断言。场景定义见下表，夹具文档见 `scripts/fixtures/SNN.md`（S01-S22, S26）。

## A 组：里程碑创建与步骤1 幂等

| ID | 前置状态 | 期望 |
|----|----------|------|
| S01 | 无里程碑文档，DEVELOPMENT.md 无下一个里程碑 | 先调 mdflow-planner，确认后进步骤1；创建文档、`git rev-parse HEAD` 写入 ref、勾选步骤1（gitignore 情形见 S14） |
| S02 | 步骤1 未勾选，文档已存在，`## Context` 无 ref | 不重建文档；补写 ref 后勾选步骤1 |
| S03 | 步骤1 未勾选，ref 已写，此后又产生新 commit | **不重新 rev-parse**，保留原 ref（基准不漂移），直接勾选 |
| S04 | 步骤1 未勾选，打回记录有「步骤2 大问题」行，文档为被打回版 | 按打回记录重写文档；保留打回记录与原 ref；勾选步骤1 |

## B 组：设计核对与打回（步骤2）

| ID | 前置状态 | 期望 |
|----|----------|------|
| S05 | 步骤1 ✓，步骤2 报告 ❌，问题为小问题（措辞级） | 改文档后重跑步骤2，步骤1 保持勾选，不产生打回记录（≤3 次内） |
| S06 | 步骤1 ✓，步骤2 报告 ❌，问题为大问题（设计方向） | 统一打回动作：取消步骤3-7 勾选、打回记录 +1、状态行重置 `第2轮｜4— 5— 6— 7—`，回到步骤1 |
| S07 | 报告 ✅，`AGENTS.md` 人工审核=开启 | 步骤2 勾选前暂停等确认；确认后勾选进步骤3 |

## C 组：审查轮（步骤4-7）

| ID | 前置状态 | 期望 |
|----|----------|------|
| S08 | 步骤3 ✓，状态行 `第1轮｜4✓ 5— 6— 7—` | 断点恢复：从步骤5 继续，不重跑步骤4 |
| S09 | 步骤3 ✓，状态行 `第1轮｜4✓ 5✓ 6✓ 7✓`，4-7 未勾选 | 轮末全 ✓ → 勾选 4/5/6/7，进步骤8 |
| S10 | 步骤3 ✓，状态行 `第1轮｜4✓ 5✗ 6✓ 7✓`，轮末判断被中断 | 统一打回：取消 3-7 勾选、打回记录 +1、状态行 `第2轮｜4— 5— 6— 7—`、下一步=步骤3 |
| S11 | 步骤3 ✓，状态行缺失，4-7 未全勾（旧里程碑） | 初始化状态行（已勾 ✓、未勾 —），从 4→5→6→7 连续跑，步骤7 后立即轮末判断 |
| S12 | 步骤4/5 审查中发现新问题 | 发现全部登记 Bugs（⬜，🔴🟡🟢 含 🟢）；本步状态写 ✗；**不勾选、不打回**，继续下一步 |
| S13 | 步骤7 执行中：已登记 2 条发现，状态行 7 仍为 —（中断） | 重入重跑步骤7；状态行保持 —，不带未登记/半写状态触发轮末 |
| S14 | 步骤7 报告 ❌（验收发现问题） | **先登记完 Bugs，再写状态行 7✗**，随后轮末统一打回 |
| S15 | 步骤5 报告含 🟢 单独存在（无 🔴🟡） | 🟢 登记入 Bugs 并置本步 ✗ → 轮末打回；不允许"🟢 不阻断"放行 |

## D 组：Bugs 表与步骤3

| ID | 前置状态 | 期望 |
|----|----------|------|
| S16 | 步骤3 ✓，状态行全 —/无轮进行，Bugs 有 ⬜ 行（mdflow-bug 中途报的） | 统一打回，打回记录原因「未修复 bug」，进步骤3 按 🔴→🟡→🟢 修复 |
| S17 | 审查轮进行中（状态行含 —），轮内步骤5 新登记 2 条 ⬜ | **不触发**步骤3 回退；轮内跑完，轮末随 ✗ 一并打回处理 |
| S18 | 步骤3 进行中：子任务 1 ✓、2 ⬜（中断后重入） | 从子任务 2 续做，不重做 1；全部 ✅ 且 Bugs 无 ⬜ 才勾选步骤3 |

## E 组：步骤8 提交与收尾

| ID | 前置状态 | 期望 |
|----|----------|------|
| S19 | 步骤7 报告 ✅ 且轮末判断完成 | 先输出里程碑完成汇报（6 段），再勾选步骤8，最后提交（汇报先于勾选） |
| S20 | 步骤8 中断：CHANGELOG 已插版本条目，未提交 | 重入跳过 CHANGELOG 插入（标题行存在即幂等），补汇报、勾选、提交；`git status` 干净则跳过提交 |
| S21 | 里程碑目录在 `.gitignore` | 步骤1/8 跳过文档 git 提交，只提交 CHANGELOG/版本文件；文档创建照常 |
| S22 | 8 步全勾 | 状态机命中入口分支「全部已完成 → 步骤1」，回到步骤1 规划/创建下一个里程碑 |

## F 组：子技能输入输出

| ID | 场景 | 期望 |
|----|------|------|
| S23 | 步骤5 调用 mdflow-review：`AGENTS.md` 无 `## 代码审查维度` | 不传 `dimensions`，技能回退内置默认 6 维；维度用 `## 审查维度` 传入则属违规（设计维度串用） |
| S24 | 步骤2/5/7 报告产出 | 文件名严格等于契约清单 `step2-design-review.md`/`step4-simplify.md`/`step5-code-review.md`/`step6-test.md`/`step7-acceptance.md`，重跑同名覆盖 |
| S25 | mdflow-bug 记录越界 bug，用户选「加入缺陷池」 | 写 `docs/BUGS.md`（含提出版本列），不写当前里程碑、不触发状态机回退；close 模式删行保表头 |

## G 组：废弃里程碑

| ID | 前置状态 | 期望 |
|----|----------|------|
| S26 | 当前里程碑 `状态=已放弃`，无其它 `进行中` 里程碑 | 状态机排除已放弃文档，命中入口分支「全部已完成 → 步骤1」，回到步骤1 规划新里程碑 |
| S27 | 有 `进行中` 里程碑 A 正常进行，里程碑 B `状态=已放弃` | 状态机选 A 继续，不受 B 影响；废弃不产生打回记录 |
